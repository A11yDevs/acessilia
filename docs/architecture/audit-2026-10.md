# Architecture audit, October 2026

> A Brazilian Portuguese translation is available in [audit-2026-10.pt-br.md](audit-2026-10.pt-br.md).

This is the audit asked for by [#152](https://github.com/A11yDevs/acessilia/issues/152). It inventories what is implemented more than once across the core, the SDK, docstruct and the Toolbox, which operational dependencies remain, and how the architecture is guarded. It records a responsible component and a recommended destination for each finding, measured against principles P1–P9 ([constitution, section 7](../constitution.md)) and ADR-0001 to ADR-0006 ([docs/adr](../adr/README.md)).

- **Snapshot:** `acessilia` `develop` at `c979344` (after #178), `acessilia-toolbox` `develop` at `bfb6d2b` (after toolbox#60).
- **Method:** every finding was checked in the code (imports, definitions, call sites) or measured; a finding that has not been checked is marked *to confirm*.

## 2. Open findings

Priority: **high** means a principle is broken today or a deployment can fail; **medium** means duplicated logic that can diverge; **low** means cleanup.

| ID | Finding | Evidence | Principles | Owner | Recommended destination | Priority |
|---|---|---|---|---|---|---|
| A1 | The processing manifest model exists twice, with the same schema id `processing-manifest:1.1.0`. The schema exists twice as well. | `backend/core/manifest/models.py` (351 lines) and `acessilia_toolbox/core/normalization/models.py` (313 lines); `schemas/processing_manifest.schema.json` in the core and the same `$id` inside the Toolbox's `structured-document@1.json` | P1, P7 | docstruct (semantic model); Toolbox (published contract) | **Decided in [ADR-0007](../adr/0007-manifest-model-and-mathml-conversion.md):** docstruct holds the single semantic model (pure, no mandatory dependency); the Toolbox derives `artifact/structured-document@1` from it, through an explicit adapter where the payload differs, and keeps publishing and validating it; operational and planning fields stay with their components. | High |
| A2 | Callout grouping is implemented twice, and the Toolbox copy hard-codes document-specific titles. | `acessilia_toolbox/core/normalization/builder.py` (`_tag_known_title_callouts`, `_is_same_callout_cluster`, `KNOWN_CALLOUT_TITLES` with phrases from one tutorial) and `docstruct/regions/grouping.py` | P1, P2 | Toolbox and docstruct | The Toolbox uses `docstruct.regions.grouping`; known titles become configuration, not code. | Medium |
| A3 | LaTeX → MathML conversion and pt-BR verbalization are implemented twice, and the two have diverged. | `backend/tools/formula_tools.py` (206 lines, used by the canonical builder and the PDDL handlers) and `acessilia_toolbox/providers/pure_math.py` (505 lines, `math.convert` and `math.verbalize`) | P1, P4 | Core and Toolbox | **Decided in [ADR-0007](../adr/0007-manifest-model-and-mathml-conversion.md):** the core calls `math.convert` and `math.verbalize` through the SDK; `latex2mathml` and the verbalization rules stay only in the Toolbox's `pure-math` provider; docstruct keeps only pure LaTeX normalization (no conversion extra, no verbalizer). `formula_tools.py` then loses `latex_to_mathml` and `verbalize_latex_fallback`, and the core drops its direct `latex2mathml` dependency once no other use remains. `math.verbalize@1` is pt-BR only, as the core's verbalizer is today. | Medium |
| A4 | The Toolbox runs an older docstruct than the core. | Toolbox `pyproject.toml` pins the `docstruct-v0.1.0` wheel; the core builds `libs/docstruct` 0.3.0 | P8, P9 | docstruct and Toolbox | Coordinated release: publish docstruct 0.3.x and bump the Toolbox. A2 and A3 depend on it. | High |
| A5 | `ArtifactRef` has two shapes and no published schema. | SDK `toolbox/artifacts.py` (provisional dataclass: `artifact_id`, `digest`) and Toolbox `core/artifact.py` (pydantic: `artifact_id`, `media_type`, `size`, `uri`, `storage_backend`, `filename`); there is no `artifact-ref@1` in the Toolbox `schemas/` | P5, P7 | Toolbox | The Toolbox publishes `artifact-ref@1` ([ADR-0005](../adr/0005-artifact-references.md)); the SDK generates its model from it. | Medium |
| A6 | The capability contract check does not run in CI. | `scripts/check_capability_contract.py` runs only offline, against `tests/fixtures/toolbox-contract.json`, which is captured by hand; neither repository's CI calls it | P7, P9 | Core and Toolbox | The Toolbox publishes its catalogue as a CI artifact or release asset; the core's CI checks the SDK registry against it. | Medium |
| A7 | Sidecar images are built by hand on the servers, so the API and a sidecar can disagree. | `pdf-ua-render:latest` is built locally (no workflow builds it, and `staging-update.sh` does not rebuild it). After toolbox#59, homologação served `document.export.docx` while the sidecar answered 404 on `/render/docx`, until it was rebuilt | P6, P9 | Toolbox | CI builds and publishes every sidecar image with the Toolbox version tag; the update scripts pull them. | High |
| A8 | The English-only guard checks 1 file out of 255. | `tests/test_no_portuguese.py` globs from `tests/` instead of the repository root (`PROJECT_ROOT = Path(__file__).parent`); the SDK alone has 47 lines with Portuguese text | P8, constitution 2.8 | Core | Scan from the repository root and `libs/`, with an allowlist of current offenders that may only shrink. | Medium |
| A9 | Some architectural guards are missing or weaker than [ADR-0002](../adr/0002-component-responsibilities.md) requires. | docstruct `test_purity.py` blocks only `backend`, `acessilia_toolbox` and `acessilia_sdk`, not every non-stdlib import; the SDK does not check that its dependencies stay within {httpx, docstruct}; the Toolbox has no test that forbids importing `acessilia_sdk` or `backend` (no offender today) | P3, P8 | docstruct, SDK, Toolbox | Add the three tests. Each passes today. | Medium |
| A10 | Text and code normalization may be implemented twice (*to confirm*). | Toolbox `pure_text.py` (255 lines, `text.postprocess`) and `pure_code.py` (221 lines, `code.normalize`) do not import docstruct; the core uses `docstruct.text` (`sanitize`, `code_reflow`) | P1 | Toolbox | Compare the behaviour; if they overlap, the providers use `docstruct.text`. | Low |
| A11 | The constitution asks for tests inside the Docker container, which cannot run them. | Constitution §3.7 ("Primary validation: pytest inside Docker container"); the image installs no test dependencies and excludes `tests/` | P8 | Core | Reword §3.7: CI on the pinned Python and dependencies is the gate, and the image gets a smoke test (as Delivery already does). | Low |
| A12 | Ten core modules only re-export docstruct. | `backend/pipeline/{canonical_builder,fusion,pandoc_ast_builder,sanitizer,semantic_rules,table_ast,validators}.py` and `backend/tools/{code_tools,region_classifier,text_processor}.py` | P3 | Core | Import docstruct directly and remove the shims, one module at a time. | Low |

No dependency cycle was found. The Toolbox imports neither `acessilia_sdk` nor `backend`, the SDK imports neither `backend` nor the Toolbox, and docstruct imports none of the three.
